### RelayHeader.spec.tsx

**New test**: "skips title update if activeThreadId changes before getThread resolves" (L169-213)
- Tests that when activeThreadId changes before a pending getThread promise resolves, the old promise's callback checks the `cancelled` flag and skips updating the title
- Creates two threads, delays t1's getThread, immediately switches to t2, verifies t2's title appears, then resolves t1's promise and confirms title hasn't changed
- Covers the `if (!cancelled)` false branch path where the cleanup has set cancelled=true but the promise callback still executes

## Uncovered Lines (Justified)

### TabBar.tsx
- **L74** (`if (!el) return;` in checkOverflow): The scrollRef.current is always set when a mounted component's effect runs. This null check is a defensive guard that cannot be triggered in normal testing without mocking the ref, which violates the "test through the public contract" rule.
- **L93-100** (ResizeObserver effect with null check): Same as L74 — the effect only runs on a mounted component with a set ref. The early return is defensive and untestable in happy-dom.
- **L273** (`if (pendingCloseTabId) closeTab(...)` in close dialog onClick): This onClick fires inside a dialog that only renders when pendingCloseTabId is set. The condition is always true in the normal flow; testing both branches would require manually clearing the value during the click, which is not a realistic user action.

### RelayHeader.tsx
- **L69** (`if (!cancelled) setTitle(...)`): The false branch (when cancelled is true) is logically testable but the coverage tool does not register it even though a test ("skips title update if activeThreadId changes before getThread resolves") exercises this path. This appears to be a quirk of how the v8 coverage engine reports promise callback branches. The test logic correctly verifies that when the effect cleanup runs before the promise resolves, the title is not updated.
