## Test IDs and Selectors Used
- `relay-launcher` - main launcher container
- `relay-launcher-search` - search input
- `relay-launcher-row` - individual rows in launcher
- `relay-launcher-section-{id}` - section headings (recent, attach, actions)
- `relay-launcher-list` - root view list container
- `relay-launcher-empty` - no-results message
- `relay-launcher-back` - back button in list view
- `relay-picker-trigger` - + button to open launcher
- `relay-composer` - composer textarea
- `relay-composer-pill` - attached item pills
- `relay-picker-row` - virtualized rows in embedded MentionMenu (for request/env lists)

## Key Implementation Insights

1. **Launcher Structure**: RelayLauncher renders root view (Recent, Attach, Actions) or list view (MentionMenu embedded) based on `data-view` attribute
2. **Keyboard Navigation**: After clicking an Attach row, the search input is focused and ready for keyboard input. Typing filters, Enter selects first match
3. **Network Isolation**: Launcher reads only from in-app stores (no network until selection triggers callback)
4. **Virtualization**: Request/environment lists use MentionMenu with virtualized `relay-picker-row` elements - not all rows are in DOM initially
5. **Styling**: At 320px viewport, launcher content fits without horizontal scroll; no CSS truncation on rows
